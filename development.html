Stack and build

The project is a Vite + React multi-page demo with shared runtime and guideline assets.

The live app and the guideline pages ship from the same codebase. The goal is to keep the runtime hero, the visual handoff, and the engineering spec aligned rather than maintaining separate sources of truth.

Stack

  • Vite for local dev and static multi-page builds.
  • React for the live demo app shell and hero runtime.
  • Shared CSS layers for the hero, header, settings panel, and docs pages.
  • Runtime glow sampling via canvas plus ResizeObserver.

Static pages

  • index.html for the live demo.
  • creative.html for creative safe-zone guidance.
  • product.html for product module guidance.
  • development.html for implementation guidance.

Project structure

Keep the live runtime, docs wiring, and source data cleanly separated.

Core runtime files

  • src/App.jsx: live demo composition, settings state, and prop wiring.
  • src/components/SiteHeader.jsx: default and countdown header variants with fixed-scroll behavior.
  • src/components/HeroBanner.jsx: responsive hero banner and carousel handoff.
  • src/components/HeroCarousel.jsx: carousel overlay and autoplay presentation.

Supporting files

  • src/config/heroDemoConfig.js: content, defaults, docs links, and preview adapters.
  • src/data/hero-banner-data.json: URL-first carousel content source.
  • src/hooks/useHeroGlow.js: desktop image/video glow sampling logic.
  • documentation.css: shared visual system for the three guideline pages.

Public contracts

These are the interfaces the live demo composes around.

SiteHeader

  • variant?: "countdown" | "default"
  • logoSrc: string
  • actions?: { label; variant; href? }[]
  • countdownTarget?: string | Date
  • countdownCta?: { label; href? }
  • eventBrand?: { logoSrc; title; subtitle }

HeroBanner

  • deck: { mode; autoplayMs?; transitionMs?; slides }
  • HeroSlide = { id; media; focus?; layout?; ctaLayout?; goldButtonNote?; logo?; label?; title?; subtitle?; price?; primaryCta?; secondaryCta?; helperText? }
  • media: { desktop; tablet; mobile } where each item is an image or video source.
  • layout?: { contentAlignment?; theme?; titleSize? }
  • focus provides authored framing; when height is constrained, horizontal focus stays while vertical crop becomes top-anchored.

Breakpoints and layout

Each breakpoint keeps its own ratio, chrome treatment, and height strategy.

Desktop

  • 1025px and above.
  • Inset 16:9 card inside the shell gutters.
  • Height still caps against the viewport after subtracting the 64px header.
  • Minimum height uses a true 34rem floor.
  • Title measure is 50%; subtitle and helper measure are 30%.
  • Glow and overlay border remain active.

Tablet

  • 768px to 1024px.
  • Creative target stays 5:7 and the hero remains full width.
  • Height prefers about 85% of the screen in normal cases.
  • Minimum height uses a true 36rem floor.
  • Title measure is 80%; subtitle and helper measure are 60%.
  • Border, radius, shadow, and glow are removed.

Mobile

  • 767px and below.
  • Creative target stays 9:16 and the hero is full-bleed.
  • Height prefers about 90% of the screen in normal cases.
  • Minimum height uses a true 38rem floor.
  • Text widths stay on the current centered mobile behavior.
  • Border, radius, shadow, and glow are removed.

Runtime behavior

Header, hero, and chrome rules should stay consistent across demo and docs.

Header rules

  • Header height is 64px.
  • Desktop header stays in normal flow on first paint, then becomes fixed once the page scrolls.
  • The dark desktop surface treatment ramps in progressively over the first 48px of scroll.
  • Tablet and mobile headers are fixed from first paint and overlay the hero.
  • On small screens, the same dark surface and blur build progressively while scrolling.

Hero rules

  • Desktop content can be left aligned or centered; tablet and mobile content stay centered.
  • Tablet and mobile use a stronger top scrim to protect the overlaid header.
  • Live media keeps the authored focus position on unconstrained layouts.
  • When hero height is capped, vertical crop switches to top-anchored while horizontal focus is preserved.
  • Gold theme applies the title accent and primary CTA gradient; standard theme returns both to the neutral style.

Glow and border system

  • Desktop only: glow is rendered inside .hero-banner-demo.
  • Desktop only: glow is sampled from the active media frame.
  • Desktop only: overlay border remains the masked vertical gradient treatment.
  • Tablet and mobile do not use sampled glow or border overlays.

Adoption notes

  • hero-banner-data.json is the content source for carousel mode.
  • heroDemoConfig.js remains the single-slide preview adapter for manual toggle mode.
  • The settings panel is demo-only and should not be treated as production product UI.
  • The dedicated creative, product, and development pages are the preferred review entry points.
